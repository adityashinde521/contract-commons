# Contract Commons

An Ethereum-focused smart contracts course with one path for every student. Learners run contracts
in Remix and Foundry, use the graphical tools professionals use (OpenZeppelin, thirdweb, Safe, Aragon,
EAS, Tenderly, Phalcon, Dune, L2BEAT), and look at every contract through three lenses: technology,
business and law. Everyone does every lab and takes the same final exam.

- 13 modules, 56 lessons and labs, every lesson in the same five steps: Problem → Concept → Build → Apply → Ship
- 33 lessons with in-depth sections, worked examples and common mistakes; 17 inline SVG diagrams
- 22 labs with an expected result for every step; lab contracts compile with Solidity 0.8.24 to 0.8.30
- A bank of 680 questions in four types: concept, fill the missing logic, fix the wrong line, put steps
  in order (no code writing). Each lesson attempt draws 10 questions; pass with 80%
- One final exam for everyone: 40 questions (10 of each type, spread across all modules), pass with 70%
- A placement check that shows which modules a learner can move through quickly
- Progress, quiz scores and a lab log saved only in the learner’s own browser (no accounts, no server, no personal data)
- Every lab runs on the Sepolia test network or reads public data. No real money is used.

**Live site:** https://adityashinde521.github.io/contract-commons/

## Maintaining the content

| Task | Command or file |
|---|---|
| Edit quiz questions | `tools/quiz_types_*.py`, `tools/quiz_more_*.py`, then `python3 tools/quiz_types.py` |
| Export the question bank for review | `python3 tools/export_questions.py` → `docs/question-bank.csv` |
| Edit in-depth sections and worked examples | `tools/deepen_*.py`, then `python3 tools/deepen.py` |
| Edit diagrams | `tools/diagrams.py`, then `python3 tools/diagrams.py` |
| Edit expected results in labs | `tools/lab_expect.py`, then `python3 tools/lab_expect.py` |
| Re-check volatile facts each semester | `docs/fact-check.md` |

## Use it offline

Run `npm install` and `npm run build` once. Then open `dist/index.html` in any browser by double-clicking it.
Everything (fonts, search, quizzes, progress) works from disk without internet or a web server.
Only the links to outside tools (Remix, Etherscan, Safe and so on) need a connection.

## Run it

```bash
npm install
npm run dev        # http://localhost:4321
npm run build      # static site in dist/
```

All links in the build are relative, so the `dist/` folder can be copied to any static host or sub-path as it is.

## Where things are

| Path | What |
|---|---|
| `src/content/lessons/*.md` | One file per lesson or lab. Frontmatter (title, module, kind, minutes, problem) plus `## Problem`, `## Concept`, `## Build` or `## Try it`, `## Apply`, `## Ship` sections in HTML. |
| `src/data/modules.json` | Module order, summaries, sources, and the lesson order inside each module |
| `src/data/quizzes.json` | Question bank per lesson. Concept items: `q`, `o` options, `a` answer index, `e` explanation. Generated by `tools/quiz_types.py`; edit the `tools/quiz_*.py` sources, not this file. |
| `src/data/glossary.json`, `src/data/placement.json` | Glossary terms and the placement check |
| `src/content/pages/*.md` | About, setup and safety, teamwork, capstone, project formats, instructor notes |
| `src/styles/tokens.css`, `src/styles/components.css` | Design tokens and components from the Contract Commons design system |
| `src/styles/site.css` | Layout and lesson-content styles |
| `public/app.js` | Client script: progress, quizzes, lab log, search, dashboard, placement |
| `design/design-system/` | The design system (tokens, component guidelines and previews) as built in Claude Design |
| `design/mockups/` | The three approved mockups (landing, dashboard, lesson). Kept as a design record; they predate the single-path change, so the site differs in places. |
| `docs/curriculum.md` | Module map and the university syllabi it was checked against |
| `docs/fact-check.md` | Volatile claims, their status and sources, with the date of the last check |

| `tools/` | Content scripts (see “Maintaining the content”), `relativize.mjs` (post-build relative links) and `open-offline.mjs` |
| `.github/workflows/` | `pages.yml` builds and deploys to GitHub Pages on every push to `main`; `build.yml` checks pull requests |

## Add or edit a lesson

1. Create `src/content/lessons/<slug>.md` with the frontmatter used by the other files.
2. Add `<slug>` to the right module’s `lessons` list in `src/data/modules.json`.
3. Add questions for `<slug>` in a `tools/quiz_*.py` file and run `python3 tools/quiz_types.py` (every lesson needs at least one item of each type).
4. Run `npm run build`. The build fails if frontmatter is missing or invalid.
