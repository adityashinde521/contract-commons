## Roles

<div class="goal"><b>Goal:</b> your team knows who does what in each lab and what you hand in.</div>
    <p>Teams have three or four students. Roles rotate every lab, so every student builds, models, analyses and records several times. The final exam is individual and the same for everyone, so nobody can specialise in one role.</p>
    <div class="tw"><table>
      <tr><th>Role</th><th>Task in a lab</th><th>Practises</th></tr>
      <tr><td><b>Builder</b></td><td>Runs Remix or the no-code tool. Reads each step aloud before doing it.</td><td>Technology lens</td></tr>
      <tr><td><b>Process analyst</b></td><td>Draws the state machine and tracks costs (gas, time, intermediaries).</td><td>Business lens</td></tr>
      <tr><td><b>Legal analyst</b></td><td>Writes the clause the code implements and lists what the code cannot express.</td><td>Law lens</td></tr>
      <tr><td><b>Recorder</b></td><td>Keeps the lab log: screenshots, addresses, transaction hashes, answers to Discuss questions.</td><td>Evidence and clear writing</td></tr>
    </table></div>

## Deliverables

<h4>Lab log (each lab)</h4>
    <ul>
      <li>One page per lab: date, team, roles, the steps you completed, screenshots of key results.</li>
      <li>All addresses and transaction hashes. For Sepolia: Etherscan links.</li>
      <li>Short answers to the Discuss questions, one paragraph per lens, written by different team members each time.</li>
      <li>One thing that went wrong and how you fixed it.</li>
    </ul>
    <h4>Portfolio (end of course)</h4>
    <ul>
      <li>A shared repository or folder with all lab logs and contracts.</li>
      <li>The capstone (P1): working contract, process model, legal text and a 10-minute presentation.</li>
    </ul>
    <div class="callout tip"><h5>How you are assessed</h5><p>The instructor notes (I3) contain the rubric: a shared part for the team (does it work, do the three parts match?) and an individual part: each student is questioned on any part of the system.</p></div>
