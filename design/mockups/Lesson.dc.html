Escrow: three parties and a state machine

Hold a buyer’s payment in a contract until delivery, with an arbiter for disputes. Then run both endings and make the contract say no.

01 · Problem

How do two strangers buy and sell safely online?

Lena sells a used laptop to Marco in another city for 1 ETH. If Marco pays first, Lena could keep the money. If Lena ships first, Marco could keep the laptop. Today a bank or a platform with buyer protection sits in the middle and takes a fee.

Your question for this lesson: can a contract hold the money instead, and what can it not decide on its own?
02 · Concept

A contract is always in exactly one state

Each function works only in the right state and only for the right party. Anything else is rejected with a revert, and nothing changes.

  1. state 0
    Awaiting payment
    Buyer pays the exact price
  2. state 1
    Awaiting delivery
    Buyer or arbiter releases; arbiter refunds
  3. state 2
    Complete
    Seller has been paid
  4. state 3
    Refunded
    Buyer has the money back
Key terms: state machine msg.sender payable wei revert

// Escrow.sol · confirmDelivery
function confirmDelivery() external inState(State.AwaitingDelivery) {
  require(msg.sender == buyer || msg.sender == arbiter, "Only buyer or arbiter");
  state = State.Complete; // effect first
  (bool ok, ) = seller.call{value: address(this).balance}("");
  require(ok, "Transfer failed");
}
04 · Apply

One contract, three readings

The arbiter acts like a judge. Who chooses it, and is its decision enforceable? The goods are partly defective, but the code knows only “all” or “nothing”. What does §441 BGB (price reduction) say?
